คู่มือนี้สำหรับคนที่ดูแลระบบต่อ โดยไม่ต้องเขียนโค้ด: ระบบอยู่ที่ไหน ต้องเฝ้าดูอะไร เกิดปัญหาแล้วแก้อย่างไร และสำรอง/กู้คืนข้อมูลอย่างไร

## 2. บัญชีและรหัสที่ต้องรักษาไว้

| สิ่งที่ต้องมี | ใช้ทำอะไร | ถ้าหาย |
|---|---|---|
| บัญชี **GitHub** `itluckswan-coder` | เก็บโค้ด อัปเดตระบบ สำรองข้อมูล กู้บัญชีผู้ดูแล | อัปเดต/สำรองข้อมูลไม่ได้ (ระบบยังรันอยู่) |
| บัญชี **Cloudflare** ของ Luck Swan (subdomain `it-luckswan`) | รันระบบและเก็บข้อมูล | **ระบบหยุดทั้งหมด** — ห้ามปล่อยให้บัญชีถูกปิด และเปิด 2-step verification |
| รหัส `BACKUP_PASSWORD` | ล็อกไฟล์สำรองข้อมูล | **เปิดไฟล์สำรองที่เคยทำไว้ไม่ได้อีกเลย** — จดเก็บในที่ปลอดภัย 2 ที่ |

**GitHub Secrets** (repo › Settings › Secrets and variables › Actions) — ค่าเหล่านี้ใส่แล้วดูย้อนหลังไม่ได้ ถ้าลืมให้สร้างใหม่แทน

| ชื่อ | คืออะไร | จำเป็น |
|---|---|---|
| `CLOUDFLARE_API_TOKEN` | สิทธิ์ให้ GitHub อัปเดตระบบบน Cloudflare (แม่แบบ *Edit Cloudflare Workers* + *Account · D1 · Edit*) | ใช่ |
| `CLOUDFLARE_ACCOUNT_ID` | เลขบัญชี Cloudflare (ตัวอักษร 0-9 a-f 32 ตัว) | ใช่ |
| `BACKUP_PASSWORD` | รหัสล็อกไฟล์สำรอง (อย่างน้อย 12 ตัว) | ใช่ — **ตอนนี้ยังไม่ได้ตั้ง ต้องตั้งก่อน** |
| `ADMIN_RESET_EMAIL` / `ADMIN_RESET_PASSWORD` | ใช้เฉพาะตอนกู้บัญชีผู้ดูแล (ข้อ 5.2) | ใส่เมื่อจะใช้ แล้วลบทิ้ง |

**กฎความปลอดภัย**
- ห้ามวาง token หรือรหัสผ่านในแชท อีเมล LINE หรือในไฟล์ใน repo — ใส่ใน GitHub Secrets เท่านั้น
- ไฟล์สำรองมีข้อมูลลูกค้า: เก็บใน Google Drive / NAS ของบริษัท และอย่าส่งรหัสไปพร้อมไฟล์
- พนักงานลาออก: ปิดบัญชีในวันสุดท้ายทันที (ข้อ 5.3)

### 4.1 ตรวจว่าเซิร์ฟเวอร์ทำงานไหม
1. เปิด https://luckswan-sales.it-luckswan.workers.dev/api/health
   - เห็น `{"ok":true, ...}` = เซิร์ฟเวอร์ปกติ › ให้ผู้ใช้กด "ลองใหม่ตอนนี้" หรือปิดแท็บแล้วเปิดใหม่
   - ขึ้น error หรือหน้าว่าง = เซิร์ฟเวอร์มีปัญหา › ทำข้อ 2
2. Cloudflare › Workers & Pages › `luckswan-sales` › **Logs / Metrics**: ดูว่ามี error เยอะไหม
3. Cloudflare › D1 › `luckswan-sales` › **Metrics**: ถ้า Rows read ของวันนี้ชนเพดาน 5 ล้าน = โควตาเต็ม
   - โควตาฟรีรีเซ็ตทุกวัน **07:00 น. เวลาไทย** (00:00 UTC) ระบบจะกลับมาเอง
   - ถ้าเกิดบ่อย หรือรอไม่ได้: อัปเกรดเป็น Workers Paid (ข้อ 7) ระบบกลับมาทันทีหลังอัปเกรด
4. ดูสถานะ Cloudflare ทั้งโลกที่ https://www.cloudflarestatus.com
5. เมื่อกลับมาปกติ: ให้ทุกคนปิดแอปแล้วเปิดใหม่ และตรวจงานที่บันทึกช่วงที่ระบบล่ม ว่าขึ้นเซิร์ฟเวอร์ครบไหม ถ้าไม่ครบให้พิมพ์ใหม่

## 5. จัดการผู้ใช้

### 5.1 ผู้ใช้ลืมรหัสผ่าน
ผู้ดูแลระบบ หรือคนที่มีสิทธิ์ "จัดการผู้ใช้": แอป › เมนู **ผู้ใช้งาน** › กด ✏️ ที่ชื่อคนนั้น › **รีเซ็ตรหัสผ่าน** › แจ้งรหัสใหม่ให้เจ้าตัวทางที่ปลอดภัย (พูดหรือโทร) และให้เปลี่ยนเองหลังเข้าระบบ
- การรีเซ็ตจะทำให้คนนั้นออกจากระบบในทุกเครื่อง
- รหัสของผู้ดูแลระบบ เปลี่ยนได้เฉพาะผู้ดูแลระบบด้วยกัน

### 5.2 ไม่มีผู้ดูแลระบบคนไหนเข้าได้ (กู้บัญชีผ่าน GitHub)
1. GitHub › repo › Settings › Secrets and variables › Actions › New repository secret สร้าง 2 ตัว:
   - `ADMIN_RESET_EMAIL` = อีเมลที่จะใช้เข้าระบบ (บัญชีเดิมหรือใหม่ก็ได้)
   - `ADMIN_RESET_PASSWORD` = รหัสผ่านชั่วคราว 8 ตัวขึ้นไป
2. Actions › **Reset admin account** › Run workflow › รอเครื่องหมายถูกสีเขียว (1–2 นาที)
3. เข้าแอปด้วยอีเมลและรหัสนั้น — บัญชีจะเป็นผู้ดูแลระบบที่มีสิทธิ์ครบ และปลดล็อกการเข้าผิดหลายครั้งแล้ว
4. **เปลี่ยนรหัสในแอปทันที** แล้วกลับไปลบ secret `ADMIN_RESET_PASSWORD`

ข้อมูลอื่นของบัญชีนั้นยังอยู่ครบ ระบบไม่แสดงข้อมูลผู้ใช้ใน log (เพราะ repo เป็นสาธารณะ)

### 5.3 พนักงานเข้าใหม่ / ลาออก / ย้ายแผนก
- **เข้าใหม่:** ผู้ใช้งาน › + เพิ่มผู้ใช้ › ใส่อีเมล บทบาท แผนก และ "สถานที่ที่เข้าได้" › แจ้งรหัสเริ่มต้นให้เปลี่ยนเมื่อเข้าครั้งแรก
- **ลาออก:** ผู้ใช้งาน › ✏️ › เปลี่ยนสถานะเป็น **ปิดใช้** (แนะนำ: ประวัติงานที่คนนั้นทำยังอยู่ครบ) แทนการลบ
- **ย้ายแผนก / เปลี่ยนตำแหน่ง:** แก้บทบาทและแผนก — สิทธิ์และเมนูเปลี่ยนตามบทบาททันที

## 6. สำรองข้อมูลและกู้คืน

### สำรอง (ทุกสัปดาห์ และก่อนทำอะไรใหญ่ทุกครั้ง)
1. GitHub › **Actions** › **Backup data** › **Run workflow**
2. รอ 1–2 นาที เปิดรายการที่ขึ้นถูกสีเขียว
3. หัวข้อ **Artifacts** › ดาวน์โหลด `luckswan-backup-<วันที่>` (ได้ .zip ที่มีไฟล์ .7z ข้างใน)
4. เก็บใน Google Drive / NAS ของบริษัท — GitHub เก็บให้แค่ 90 วัน

ไฟล์สำรองมีครบทุกอย่าง: ฐานข้อมูลทั้งหมด (รวมรูปที่อัปโหลด) + โค้ดพร้อมประวัติ + วิธีกู้คืน · เปิดด้วย 7-Zip (Windows) หรือ Keka (Mac) โดยใส่ `BACKUP_PASSWORD`

### ทดสอบไฟล์สำรอง (ทุก 3 เดือน)
แตกไฟล์ .7z ล่าสุดด้วยรหัส แล้วดูว่ามี `database.sql` ขนาดไม่เป็น 0 — ถ้าเปิดไม่ได้ แปลว่ารหัสที่จดไว้ไม่ตรง ต้องแก้ทันทีก่อนจะจำเป็นต้องใช้จริง

### กู้คืน
ทำตาม `docs/backup/RESTORE.md` (มีทั้งย้ายไปบัญชีใหม่ และกู้ทับระบบเดิม) — **สำรองข้อมูลปัจจุบันก่อนกู้ทับทุกครั้ง** และถ้าไม่มั่นใจ ให้หยุดและขอผู้ที่มีความรู้ช่วย

## 7. โควตาฟรีของ Cloudflare และเมื่อไหร่ควรจ่ายเงิน

| รายการ | แพ็กเกจฟรี | Workers Paid ($5/เดือน) |
|---|---|---|
| D1 อ่านข้อมูล (Rows read) | 5 ล้านแถว/วัน | 25,000 ล้านแถว/เดือน |
| D1 เขียนข้อมูล (Rows written) | 100,000 แถว/วัน | 50 ล้านแถว/เดือน |
| D1 พื้นที่เก็บ | 5 GB | 5 GB (+ จ่ายตามใช้) |
| คำขอเข้า Worker | 100,000 ครั้ง/วัน | 10 ล้านครั้ง/เดือน |

- โควตาฟรีใช้ร่วมกันทุก Worker ในบัญชีเดียวกัน
- **ควรอัปเกรดเมื่อ:** โควตาเต็มเกินเดือนละ 1 ครั้ง หรือ Rows read ต่อวันเกิน 3–4 ล้านเป็นประจำ
- วิธีอัปเกรด: Cloudflare › Workers & Pages › Plans › **Workers Paid** (ไม่ต้องแก้โค้ด ไม่ต้อง deploy ใหม่)
- ตัวเลขข้างบนเป็นของเดือน พ.ย. 2569 ตรวจราคาล่าสุดที่ https://developers.cloudflare.com/d1/platform/pricing/

1. https://dash.cloudflare.com › รูปโปรไฟล์ › **My Profile** › **API Tokens** › **Create Token**
2. เลือกแม่แบบ **Edit Cloudflare Workers** › กด *Add more* เพิ่มสิทธิ์ **Account · D1 · Edit** › Continue › Create
3. คัดลอก token (แสดงครั้งเดียว) › GitHub › Settings › Secrets and variables › Actions › แก้ `CLOUDFLARE_API_TOKEN` › วาง › Update
4. ลบ token เก่าในหน้า API Tokens
5. ทดสอบ: Actions › Deploy to Cloudflare › Run workflow ต้องขึ้นสีเขียว

## 9. อัปเดต/แก้ไขระบบ (สำหรับนักพัฒนา)
- โค้ดหน้าเว็บอยู่ใน `sales-app/` · เซิร์ฟเวอร์และกฎสิทธิ์อยู่ใน `worker/src/index.js` · ฐานข้อมูลเปลี่ยนโครงสร้างผ่าน `worker/migrations/`
- ขั้นตอน: แตก branch จาก `main` › แก้ › ทดสอบในเครื่อง (`worker/DEPLOY.md` หัวข้อ "ทดสอบบนเครื่อง") › เปิด Pull Request › merge › Actions จะ deploy เอง
- **ทุกครั้งที่แก้ไฟล์ใน `sales-app/`** ต้องเพิ่มเลขเวอร์ชันใน `sales-app/sw.js` (บรรทัด `const CACHE = 'ls-sales-vNNN'`) ไม่เช่นนั้นเครื่องผู้ใช้จะยังใช้ไฟล์เก่า
- กฎสิทธิ์สำคัญ (ใครแก้อะไรได้, การอนุมัติใบเสนอราคา/ใบฟังก์ชัน) ตรวจที่เซิร์ฟเวอร์ใน `worker/src/index.js` — แก้แค่หน้าเว็บไม่พอ
- อย่า merge ในช่วงที่พนักงานใช้งานหนัก ถ้าไม่จำเป็น และสำรองข้อมูลก่อนเปลี่ยนโครงสร้างฐานข้อมูลทุกครั้ง
- Workflow `Remove the old ShawPlus from this account` เป็นของระบบอื่น (ร้านยา) ใช้ครั้งเดียว — **ไม่ต้องกด** และไม่เกี่ยวกับ LUX
